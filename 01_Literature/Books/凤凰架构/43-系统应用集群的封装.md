## 核心洞察

容器封装经历了从系统封装(LXC)到应用封装(Docker)再到集群封装(Kubernetes)的三次跃迁。Docker的成功在于产品理念与生态，而非技术壁垒。

## 详细笔记

### 1. 封装理念的三次跃迁

| 阶段     | 代表技术            | 封装对象    | 核心价值                                     |
| ------ | --------------- | ------- | ---------------------------------------- |
| 系统封装   | LXC (2008)      | 虚拟化轻量级系统 | 以系统为中心，无法快速构建差异化环境（如LAMP→LNMP需重做模板）       |
| 应用封装   | Docker (2013)   | 封装应用而非机器 | 镜像分层、版本控制、自动构建，实现分钟级环境交付                 |
| 集群封装   | Kubernetes(2014) | 虚拟化集群基础设施 | 跨数据中心的绿色部署，自动扩缩容，实现云原生能力 |

### 2. Docker成功的本质

核心不是技术壁垒，而是产品理念与生态：

- ✅ 跨机器绿色部署：应用+依赖打包，环境一致性
- ✅ 应用为中心设计：CLI/API/文档全部围绕应用
- ✅ 开发者体验：
  - Git式镜像版本管理
  - 基础镜像复用机制
  - 公共镜像仓库生态
  - 自动构建工具链

> 技术细节：早期Docker仅100+行Shell脚本即可实现核心功能(Bocker)，其价值在于标准化了应用交付范式。

### 3. 容器运行时架构演进

**关键组件关系**
- OCI标准 -> Runtime(runC) + Image Format + Distribution
- containerd -> Docker Engine / CRI-O / Kubernetes

**K8s容器运行时调用链变迁**

| 时期        | 调用链                                                  | 特点                   |
| --------- | ---------------------------------------------------- | -------------------- |
| 2014-2016 | K8s→DockerManager→Docker Engine→containerd→runC      | 完全绑定Docker           |
| 2016-2018 | K8s→CRI→DockerShim→Docker Engine→containerd→runC     | 引入CRI标准，解耦开始         |
| 2018+     | K8s→CRI→containerd→runC                              | 主流云厂商已采用此架构          |
| 2021+     | K8s v1.23+ 移除Dockershim                              | Docker Engine正式退出K8s生态 |

### 4. 技术演进关键节点

- 2015：OCI成立（Docker主导）→ 容器标准化开端
- 2016：containerd捐献CNCF → 运行时与引擎分离
- 2017：CRI-O发布 → 厂商联合对抗Docker垄断
- 2021：K8s移除Dockershim → Docker Engine退出编排领域

### 5. 工程师实践指南

**当前环境选择**：
- 开发/测试：Docker CLI（生态完善，体验最佳）
- 生产K8s集群：containerd（阿里云ACK/腾讯云TKE默认）
- 高安全场景：gVisor/Kata Containers（替代runC）

**关键认知**：
- ❌ 不要再写`docker build`在K8s YAML中
- ✅ 了解containerd CLI (`ctr`, `crictl`)
- ✅ 掌握OCI镜像规范（构建/签名/分发）

> 趋势判断：Docker CLI和Hub生态会长期存在（开发者习惯），但生产环境运行时已转向containerd+runC。掌握CRI/OCI标准比熟悉Docker命令更重要。

## 相关思考

容器封装的演进体现了从单机到集群、从技术到生态的发展趋势。理解OCI/CRI标准对于把握容器技术的未来方向至关重要。
