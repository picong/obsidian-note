# 分布式架构-47-虚拟化网络设备与容器通信原理

## 💡 核心观点
虚拟化网络设备是构建容器网络的基础，主要包括虚拟网卡(tun/tap、veth)、虚拟交换机(Linux Bridge)和Overlay网络(VXLAN)。Docker提供了多种网络模式来满足不同场景的容器通信需求。

## 📝 详细笔记

### 虚拟化网络设备

#### 虚拟网卡：tun/tap 与 veth

| 设备      | 模拟层级                        | 功能特点                                            | 使用场景                                        |
| ------- | --------------------------- | ----------------------------------------------- | ------------------------------------------- |
| tun/tap | tap：二层(以太帧)<br>tun：三层(IP报文) | 连接网络协议栈与用户态程序(/dev/net/tun)。数据包可被用户程序截获、修改、再封装。 | VPN、数据压缩、流量加密、透明代理等，适用范围广，但有性能损耗(两次协议栈)。    |
| veth    | 二层(以太网)                     | 成对出现，模拟交叉网线连接的一对网卡。一端输入数据，另一端原样流出。              | 容器间直接通信。性能优于tun/tap(不反复经过协议栈)，但不能解决多容器通信问题。 |

#### 虚拟交换机：Linux Bridge
- 本质：Linux系统下的虚拟交换机(二层转发工具)，由brctl命令创建。
- 功能：实现多容器通信，可接入真实的物理设备(eth0)或虚拟设备(veth、tap)。
- 转发规则(基于MAC地址)：
  - 广播帧：转发给所有接入设备。
  - 未知单播帧：洪泛(Flooding)，并学习MAC地址(MAC Learning)到转发表。
  - 已知单播帧：直接转发到指定设备。
  - 环路处理：实现生成树协议(STP)防止环路。
- 特殊性(与物理交换机的区别)：Linux Bridge允许给自己设置IP地址，隐式连接主机协议栈。

#### Overlay网络：VXLAN
- 背景：为了解决传统VLAN的VLAN ID数量限制(4096)和跨数据中心的传递问题。
- 核心思路(SDN)：在下层物理网络(Underlay)之上，构造上层逻辑网络(Overlay)，实现流量灵活控制。
- 原理：采用L2 over L4 (Mac in UDP)封装模式。
  - 将二层以太帧放入四层UDP报文体，并加入VXLAN Header。
  - VXLAN ID占24 bit，支持2^24 ≈ 1677万个不同的值。
- VTEP(VXLAN Tunnel Endpoints)：负责VXLAN报文的封包和解包，可以是物理或虚拟设备(如配置后的Linux Bridge)。

#### 副本网卡：MACVLAN
- 设计思路：借鉴VLAN子接口概念，在同一张物理网卡上设置多个MAC地址。
- 原理：在物理设备之上生成多个虚拟Device，每个Device有独立的MAC地址，物理网卡根据目标MAC地址判断交给哪个Device处理。
- 优势(与Linux Bridge相比)：
  - 轻量高效：通信只比物理网卡多一次MAC地址判断，性能高。
  - 实现简单：MAC地址静态，无需复杂的MAC地址学习、STP协议。

### Docker提供的容器通信方案

#### 开箱即用的网络

| 模式       | 参数               | 核心原理                                            | 优点/缺点                                   |
| -------- | ---------------- | ----------------------------------------------- | --------------------------------------- |
| Bridge   | --network=bridge | 容器独有网络名称空间 + veth pair + 接入docker0网桥 + 主机NAT转换。 | 默认配置，容器间二层通信，与外部三层通信(NAT)。              |
| Host(主机) | --network=host   | 不创建独立网络名称空间，直接使用宿主机网络设施。                        | 优点：无NAT性能损耗。<br>缺点：无隔离，易发生网络资源冲突(如端口号)。 |
| None(空)  | --network=none   | 创建独立网络名称空间，但不创建任何网络设备(只有回环设备)。                  | 方便用户自定义网络配置和管理IP地址。                     |

#### 用户自行创建的网络
- Container(容器模式)：
  - 参数：--network=container:容器名称
  - 原理：加入指定容器的网络名称空间，共享一切网络资源。
  - 应用：两个容器间可使用localhost通信，常用于sidecar模式。
- MACVLAN模式：
  - 创建：docker network create -d macvlan
  - 原理：为容器指定一个副本网卡，直接通过副本网卡的MAC地址使用宿主机物理设备。
  - 应用：追求高性能的场合。
- Overlay模式(VXLAN)：
  - 创建：docker network create -d overlay
  - 原理：特指VXLAN，用于跨主机的服务通信。
  - 应用：Docker Swarm，但因Swarm非主流，故较少使用。
