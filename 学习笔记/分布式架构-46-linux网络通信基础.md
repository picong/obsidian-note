# 分布式架构-46-linux网络通信基础

## 💡 核心观点
Linux系统的网络通信遵循OSI七层模型或TCP/IP四层模型，呈现出"逐层调用，逐层封装"的特点，被称为Linux网络协议栈。Netfilter框架提供了通用的、可供代码干预数据在协议栈中流转的过滤器机制，是Linux网络大厦的核心基石。

## 📝 详细笔记

### Linux系统下的网络通信模型
Linux系统的通信过程遵循OSI七层模型或TCP/IP四层模型，呈现出"逐层调用，逐层封装"的特点，被称为Linux网络协议栈(网络栈)。

核心原则：
- 发送数据：是层层封包，加入协议头，传给下一层。
- 接收数据：是层层解包，提取协议体，传给上一层。
- 网络栈位置：几乎整个网络栈(应用层以下)都位于系统内核空间，以保证数据安全隔离。

### 干预网络通信的NetFilter框架
Netfilter是Linux内核提供的通用的、可供代码干预数据在协议栈中流转的过滤器框架，是Linux网络大厦的核心基石。

Netfilter围绕网络层(IP协议)埋下了五个钩子，数据包流经这些位置时，会触发注册的回调函数，从而干预网络通信。

| 钩子名称        | 触发时机                        | 典型应用场景         |
| ----------- | --------------------------- | -------------- |
| PREROUTING  | 数据包刚进入协议栈后(在IP路由之前)         | 目标网络地址转换(DNAT) |
| INPUT       | IP路由后，确定是发往本机进程             | 加工发往本地进程的数据包   |
| FORWARD     | IP路由后，确定是转发给其他机器            | 处理转发到其他机器的数据包  |
| OUTPUT      | 从本机程序发出的数据包，在IP路由前          | 加工本地进程的输出数据包   |
| POSTROUTING | 从本机网卡发出去的数据包(无论是本地发出的还是转发的) | 源网络地址转换(SNAT)  |

### Xtables系列工具(如iptables)
iptables是基于Netfilter框架设计的最广泛使用的IP包过滤器，它允许系统管理员通过配置来实现原本需要使用Netfilter编码才能实现的功能。

- 设计目的：用配置实现Netfilter的常规功能，便于系统管理员日常运维。
- 预置行为(Target)：如`DROP`(丢弃)、`REJECT`(拒绝)、`ACCEPT`(放行)、`JUMP`(跳转到用户自定义链)、`DNAT`、`SNAT`(地址转换)等。
- 规则表(Table)：iptables内置了五张不可扩展的规则表，用于区分不同目的的操作。
  - 优先级：raw -> mangle -> nat -> filter -> security
  - 常用表：
    - nat表：用于网络地址转换(NAT)，如SNAT/DNAT。
    - filter表：用于数据包过滤，实现防火墙功能(ACCEPT/DROP/REJECT)

### Linux网络名称空间与容器
- Linux网络名称空间：提供了最高的隔离度，为名称空间内的进程提供了全套的网络设施(独立的设备、路由表、IP地址、iptables规则、协议栈等)。
- 容器通信问题：容器以Linux名称空间为基础实现隔离，因此容器之间、容器与宿主之间、跨物理网络之间的通信问题，自然由Linux网络虚拟化技术来解决。
