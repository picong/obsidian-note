# 分布式架构-51-Kubernetes存储生态系统

## 💡 核心观点
存储类型的划分应基于外部访问接口形式，而非内部数据存储方式。块存储、文件存储和对象存储各有特点和适用场景，没有包打天下的存储方案。文件存储是容器环境的首选，对象存储是成本和容量的首选，块存储是极致性能的首选。

## 📝 详细笔记

### 三大存储类型对比

| 存储类型                    | 接口形式                   | 数据接口/访问方式              | 核心特点与优势                | 典型应用场景           | 访问模式限制(k8s)          |
| ----------------------- | ---------------------- | ---------------------- | ---------------------- | ---------------- | -------------------- |
| 块存储(Block Storage)     | 底层协议(SCSI,iSCSI,SATA,SAS) | 固定长度的块(Block);通过LBA寻址 | 性能最优秀(高吞吐,低延迟)        | 系统引导卷，Oracle数据库 | RWO(ReadWriteOnce)   |
| 文件存储(File Storage)    | POSIX接口(如NFS、SMB)       | 文件、目录、权限组成的树           | 最贴近人类用户,支持共享           | 绝大多数容器工作负载的首选    | RWM(ReadWriteMany)   |
| 对象存储(Object Storage)  | REST Endpoint(如S3 API)  | 扁平化的K/V(对象)结构          | 容量庞大，易于共享              | CDN、图片/音视频;数据归档等 | 程序代码访问               |

### 文件存储的实现原理
- 文件系统(File System，如FAT32,NTFS,ext4)是定义文件分配表(FAT)如何实现、存储信息和提供功能标准的。
- 文件系统将不连续的块组织起来构成文件，并通过加入元数据(逻辑位置、权限、时间等)形成目录和高级功能。

### 对象存储的实现原理
- "对象"是元数据 + 逻辑数据块的组合，具有全局唯一标识(UUID)。
- 元数据集中存放，数据块分散存放在OSD(Object Storage Device)服务器上。
- 访问时需先查询元数据，确定数据块位置，延迟相对较高，但能提供高吞吐量(多OSD同时发送数据)。

### 云计算厂商存储服务对比(以AWS为例)

| 服务名称    | 对应类型 | 关键特性                                | 优势                | 适用性建议                  |
| ------- | ---- | ----------------------------------- | ----------------- | ---------------------- |
| AWS EBS | 块存储  | 原始、未格式化的块设备；必须依附于EC2(云计算主机)。        | 延迟低;性能高           | 系统引导卷;追求极致磁盘IO的大型数据库   |
| AWS EFS | 文件存储 | 完全托管的NFS;兼容POSIX                    | 可被共享;完全自动,实时扩缩;无需Attach | 大部分工作负载的首选存储           |
| AWS S3  | 对象存储 | 通常以REST Endpoint形式对外服务/存储网关转化为NFS挂载 | 价格低廉;无需考虑容量、维护    | 备份归档、容灾恢复、静态页面托管       |

### 选择建议
- 没有包打天下的存储方案。不同业务系统的场景和需求不同，对存储的诉求也不同，因此需要根据具体需求进行选择。
- 文件存储(EFS类)是容器环境的首选：考虑到容器应用通常需要共享访问、动态弹性以及易用性，文件存储是最均衡的选择。
- 对象存储(S3类)是成本和容量的首选：对于大容量、低访问频率的数据(归档、备份)或静态内容分发，其低廉的价格和分布式特性是最佳选择。
- 块存储(EBS类)是极致性能的首选：仅适用于对磁盘I/O有极高要求且能接受单节点独占的特殊工作负载(如特定的数据库)。
